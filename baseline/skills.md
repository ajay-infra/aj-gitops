# skills.md — aj-cluster-baseline

## Purpose
GitOps manifest repository synced to every registered workload cluster by ArgoCD
(via `applicationsets/workload/aj-cluster-baseline.yaml` in `aj-platform-gitops`). Terraform
never touches these resources — everything here is applied by ArgoCD only. No
`source =` module usage; not consumed as a Terraform module by anything.

## Type
`gitops-manifests`

## Repo layout

```
external-secrets/   — ExternalSecret + ClusterSecretStore (ESO → Secrets Manager)
falcon/              — CrowdStrike Falcon sensor DaemonSet
karpenter/
  node-classes/      — EC2NodeClass (instance types, AMI, user-data)
  node-pools/        — NodePool (backend, frontend, gpu)
keda/                — ScaledObject (event-driven pod autoscaling)
kong/                — KongPlugin CRDs (JWT, rate-limiting, correlation-id)
namespaces/          — platform-namespaces.yaml, workload-namespaces.yaml
policies/
  templates/         — OPA Gatekeeper ConstraintTemplate (Rego)
  constraints/       — OPA Gatekeeper Constraint (per-namespace enforcement)
  mutations/         — AssignImage (ECR pull-through cache rewrite, per public registry)
.sops.yaml           — SOPS→KMS key mapping per env (currently placeholder ARNs — see CLAUDE.md TODOs)
```

No `rbac/` directory yet — `aj-infra-rbac/.github/workflows/apply.yml` syncs
`cluster-roles.yaml`/`cluster-role-bindings.yaml` here via PR when run with
`target=k8s`, but that sync hasn't happened yet (repo is new).

No `cloudability/` directory yet — see CLAUDE.md Known TODOs.

## How changes land
Direct PR to this repo (not generated by a farm skill for most files) — edit or add
YAML, open a PR, CI validates (yamllint + kubeconform + OPA Rego lint), merge → ArgoCD
auto-syncs to dev + staging within ~30s, prod requires manual sync approval in the
ArgoCD UI. `add-opa-policy` in `aj-skill-farm` is the one skill that generates files
here directly (`policies/templates/<name>.yaml` + `policies/constraints/<name>.yaml`).

## OPA Gatekeeper enforcement
`enforcementAction: warn` in dev/staging, `deny` in prod — encoded per-Constraint YAML,
no per-env file paths needed. Mutation policies (image rewrites) apply to all
environments unconditionally.

## Branching convention
- `main` — active development, ArgoCD syncs directly from here
- No tags — this repo isn't consumed as a versioned module by anything

## CI checks
`yamllint` (per-directory, does NOT include a nonexistent `cloudability/` — see CLAUDE.md),
`kubeconform` (native K8s resources only — OPA/Karpenter/KEDA/Kong CRDs aren't in the
default schema and are skipped via `-ignore-missing-schemas`), OPA Rego lint on every
`policies/templates/*.yaml`. CI is `pull_request`-triggered only, not on push to `main`.
